# New APIs in the Xcode 27 SDKs that matter to LeoPhoneAgent

Source: locally installed Xcode 27.0 (build 27A266a; interfaces generated by Swift 6.4).
Read-only static scan of the SDK files; nothing was built or run.

- iOS/iPadOS SDK: `/Applications/Xcode.app/Contents/Developer/Platforms/iPhoneOS.platform/Developer/SDKs/iPhoneOS27.0.sdk`
- watchOS SDK: `/Applications/Xcode.app/Contents/Developer/Platforms/WatchOS.platform/Developer/SDKs/WatchOS27.0.sdk`

## 0. Method, evidence format, short answers

### How the list was produced
- Every `arm64e` Swift interface and every ObjC header was scanned for version-27 introductions and deprecations: `@available(... iOS 27 ...)`, `iOS, introduced: 27`, `API_AVAILABLE(... ios(27[.0]) ...)`, the watchOS equivalents, `deprecated: 27`, and `API_DEPRECATED(..., ios(x, 27))`.
- **Important:** the 27 SDK adds a unified availability domain. Many new APIs are written as `@available(anyAppleOS 27, *)` (Swift) or `API_AVAILABLE(anyappleos(27.0))` (ObjC), and multi-platform lists use `iOS 27` without `.0`. A search for `@available(iOS 27` alone misses most of them, for example all new Speech API.
- Declarations inside an extension that is itself marked 27 count as new. The "Availability as written" column then shows the extension's attribute, labelled `(on enclosing extension)`.
- **Brand-new frameworks** were found by comparing framework directory names with the installed **iOS 26.5 / watchOS 26.5 simulator runtimes** (`/Library/Developer/CoreSimulator/Volumes/iOS_23F77/...`, `.../watchOS_23T570/...`). The result was then filtered to frameworks whose every iOS (or watchOS) availability annotation is 27. That filter removes device-only frameworks that are simply missing from the simulator.

### Reading the Evidence column
- `X.swiftinterface:N` → `<SDK>/System/Library/Frameworks/X.framework/Modules/X.swiftmodule/arm64e-apple-ios.swiftinterface` line N. On watchOS it is `arm64e-apple-watchos.swiftinterface`. `CoreAIRuntime.swiftinterface` lives under `<SDK>/System/Library/SubFrameworks/`.
- `usr/lib/swift/X.swiftinterface:N` → `<SDK>/usr/lib/swift/X.swiftmodule/arm64e-apple-ios.swiftinterface` (Observation, _Concurrency and the AVFoundation overlay).
- `Fw/Header.h:N` → `<SDK>/System/Library/Frameworks/Fw.framework/Headers/Header.h`. N is the first line of the declaration statement.
- Platform(s) says "iOS, watchOS" only when the same declaration was also found as new in the watchOS 27 interface. That second location is given after `watchOS`.

### Deployment impact (applies to every row)
The app targets **iOS 26.0 / watchOS 26.0**, so every symbol below needs `if #available(iOS 27, *)` / `@available(iOS 27, *)` (watch: `watchOS 27`). `anyAppleOS 27` is the same version-27 gate on each platform.
Recommendation, not an SDK fact: frameworks that do not exist on 26 should be weak-linked (set to Optional). This covers **FoundationModels on watchOS**, CoreAI, SuggestedActions and the new `_X_Y` cross-import overlays.

## 2. Most valuable, by device (ranked)

Every item is 27-only. Keep the current iOS 26 / watchOS 26 path and add the 27 path behind `if #available(iOS 27, *)` / `if #available(watchOS 27, *)`. Evidence for each item is in the tables in section 1.

### Most valuable for iPhone
1. **FoundationModels custom `LanguageModel` + `LanguageModelExecutor`.** Drive `LanguageModelSession` against the app's own cloud model: tools, `@Generable`, streaming, `Transcript`. The same session code can also switch to `SystemLanguageModel` (on-device) or `PrivateCloudComputeLanguageModel`. This removes the hand-written tool-call/stream plumbing. Related 27 helpers: `Transcript` is now mutable (in-place context compaction), `session.usage` gives token budgets, `GenerationOptions.ToolCallingMode` can force or forbid tools per step, and `ContextOptions.ReasoningLevel` sets thinking effort.
   *Deployment:* all of it is new in 27, so keep the current client for 26 and route through the new session only on 27.
2. **`PrivateCloudComputeLanguageModel`.** A larger Apple model through the same session API, with `availability` and `quotaUsage` (the `QuotaLimitReached` error has a reset date). It is a cheaper fallback than the paid API for summaries and titles.
   *Deployment:* 27-only, plus the managed entitlement described in the SDK doc comment.
3. **`LongRunningIntent.performBackgroundTask` + Foundation `ProgressReporter`/`Subprogress`.** Siri, Shortcuts and App Shortcut runs no longer die at the classic ~30 s limit, and progress stays in sync with the Live Activity.
   *Deployment:* add the protocol conformance only in a 27-gated intent, or give the intent a 26 fallback that opens the app.
4. **Speech `CaptureInputSequenceProvider` / `AnalyzerInputConverter` + AVAudioSession async activate/deactivate.** These delete the hand-rolled `AVAudioEngine` tap and `AVAudioConverter` glue for SpeechAnalyzer. Buffers stay zero-copy (`CMReadySampleBuffer`), and session (de)activation no longer blocks the main thread before and after TTS.
   *Deployment:* 27-gated. Also migrate interruption handling (see deprecations).
5. **`systemPrefersReducedResourceUsage`** (SwiftUI environment, UIKit trait, application property and notification). Lower token-animation frame rates, pause terminal redraw and prefetch when the system asks. This is a direct "lighter" knob.
   *Deployment:* read it only on 27. On 26, assume false.
6. **Live Activity / Dynamic Island: `isDynamicIslandLimitedInWidth`.** Switch to a shorter compact/minimal agent-status layout when the island is narrow. ActivityKit itself has no 27 changes; the only other WidgetKit addition is `systemExtraLargePortrait`.
   *Deployment:* `@Environment` read inside a 27 check in the widget extension.
7. **`BGTaskScheduler.submitTaskRequest(_:) async throws` + SwiftUI `BackgroundTask.processingTask(_:)`.** Non-blocking submission that surfaces every error, and a SwiftUI-native handler for processing tasks.
   *Deployment:* 27 path. `submit(_:)` stays for 26 and is deprecated on 27.
8. **AppIntents polish for Siri, Controls and Live Activity buttons.** `IntentSystemContext.isVoiceOnly` gives spoken-length answers. `allowedExecutionTargets` runs an intent in the lighter App Intents or widget extension instead of launching the app. `CustomAppIntentErrorConvertible` gives proper error dialogs. `RelevantEntities` surfaces the running task. `UNMutableNotificationContent.appEntityIdentifiers` ties "run finished" notifications to the entity.
   *Deployment:* 27-gated static properties on the intent types.
9. **Chat-UI SwiftUI additions:**
   - `toolbarMinimizationBehavior(.onScrollDown, for: .navigationBar)` gives more room while streaming.
   - `swipeActions(...)` + `swipeActionsContainer()` work on LazyVStack rows.
   - `alert(error:)`.
   - `AsyncImage(request:)` + `asyncImageURLSession(_:)` load authenticated tool images and file thumbnails with the app's URLSession.
   - `dismissalConfirmationDialog` guards unsent prompts.
   *Deployment:* 27 check. Put the modifiers in `ViewModifier`s that branch on availability.
10. **WebKit browser automation.** `WKContentWorld.Configuration` can pierce closed shadow roots and enables JS handles and node snapshots. `WKJSHandle` and `WKDOMNodeSnapshot` give stable element references across calls and navigations. `willSubmitForm` lets the user confirm before the agent submits. `addBuffer` passes large data to scripts without a JSON round-trip. The result is fewer re-queries and fewer serialization costs.
    *Deployment:* 27 path. Keep the current selector-based automation for 26.
11. **Ready-made model tools: `SpotlightSearchTool`, `OCRTool`, `Attachment(UIImage)`.** The agent can search its own Spotlight index (chat history, files), OCR screenshots on device and take image input without custom tools.
    *Deployment:* 27, and the model must be driven through a `LanguageModelSession`.
12. **`withTaskCancellationShield` (+ `Task.name`) and MetricKit `MetricManager`/`trackLaunchTask`.** Guaranteed cleanup when the user cancels a run (persist the transcript, end the Live Activity), and async-stream hang and launch diagnostics to measure the smoothness work.
    *Deployment:* 27 only.

    *Deployment:* 27, iOS only.
12. **`WidgetFamily.systemExtraLargePortrait`** for a tall "recent runs" widget on the iPad Home Screen.
    *Deployment:* add the family conditionally in `supportedFamilies` on 27.

### Most valuable for Apple Watch
1. **FoundationModels arrives on watchOS 27. It is a session API, not an on-device model.** Implement a custom `LanguageModel` + `LanguageModelExecutor` over the existing URLSession/cellular model call. The watch then shares `LanguageModelSession`, `Tool`, `@Generable`, streaming and `Transcript` code with the phone. `SystemLanguageModel` is unavailable on watchOS, so on-device inference on the watch is not possible. `LanguageModelSession(model:...)` must be given an explicit model.
   *Deployment:* the framework does not exist on watchOS 26. Weak-link it and gate with `#available(watchOS 27, *)`.
2. **`PrivateCloudComputeLanguageModel` on the wrist.** It gives the watch an Apple-hosted model with no extra backend, using the same entitlement and quota rules as on the phone.
   *Deployment:* watchOS 27, the entitlement, and network access.
3. **Audio session for read-aloud.** New `AVAudioSession.deactivate(options:completionHandler:)` (non-blocking), `didBecomeInactive` / `resumptionRecommendation` notifications with contexts (old interruption notifications are deprecated on watchOS too), and Sendable `installAudioTap` / `AVReadOnlyAudioPCMBuffer`. The result is a smoother TTS hand-off with less main-thread blocking. `activate(options:)` already existed on watchOS 5.
   *Deployment:* watchOS 27.
4. **Voice-first App Intents.** `IntentSystemContext.isVoiceOnly` returns short spoken answers. `LongRunningIntent` covers longer wrist-initiated tasks. `RelevantEntities` surfaces the active run. `CustomAppIntentErrorConvertible` and `allowedExecutionTargets` are also available.
   *Deployment:* watchOS 27.
5. **`systemPrefersReducedResourceUsage` in SwiftUI (watchOS 27).** Back off animations and polling when the watch asks.
   *Deployment:* watchOS 27.
6. **Network `NetworkConnection.onPathUpdate` / `onViabilityUpdate` / `onBetterPathUpdate`.** Recover streams on Wi-Fi, Bluetooth and cellular switches. This only helps if the watch uses Network.framework's `NetworkConnection`; plain URLSession gains nothing here.
   *Deployment:* watchOS 27.
7. **SwiftUI on watch:**
   - `swipeActions` container form on non-List rows.
   - `alert(error:)`.
   - `AsyncImage(request:)` + `asyncImageURLSession`.
   - `TextFieldStyle.bordered`.
   - `NavigationTransition.crossFade`, which is cheap.
   - `reorderable()`.
   *Deployment:* watchOS 27.
8. **Lighter state plumbing.** Foundation `ProgressReporter`/`Subprogress`, Observation `withContinuousObservation`, and `withTaskCancellationShield` for clean cancel of a voice request.
   *Deployment:* watchOS 27.
9. **SwiftData sectioned `@Query` / `ResultsObserver`**, if the watch keeps local history.
   *Deployment:* watchOS 27.
10. **`UNMutableNotificationContent.appEntityIdentifiers` (watchOS 27)** links "answer ready" notifications to the conversation entity.

Not available on the watch, so plan around it: Speech/SpeechAnalyzer (absent; keep `TextFieldLink` dictation), OCR (no `RecognizeTextRequest`/`OCRTool`), on-device `SystemLanguageModel`, and BackgroundTasks (headers present, all `API_UNAVAILABLE(watchos)`). The SwiftUI `BackgroundTask.processingTask(_:)` is marked watchOS 27 in the watch interface, but no watchOS way to schedule a BGProcessingTask was found. WatchKit, WatchConnectivity, WidgetKit (watch), ClockKit, TipKit and UserNotifications have no 27 changes.

## 4. Caveats
- **SDK files only.** No runtime behaviour was verified. Doc snippets quoted above come from the `.swiftdoc` files and header comments shipped in the SDK.
- **Underscored / internal-doc symbols.** `_ModelDelegationIntent` and its types are marked `@_documentation(visibility: internal)`. Treat them as not yet a supported public API.
- **Entitlements stated in the SDK docs.** `PrivateCloudComputeLanguageModel` requires a managed entitlement ("request access to the managed entitlement"). `SuggestedActions` requires `com.apple.developer.suggested-actions`.
- **Scanner precision.** The tables were produced by a line-oriented scanner. Counts can include a few non-public (`package`/`internal`) declarations that appear in the interfaces. Every row in the curated tables was checked against the file and line shown.
