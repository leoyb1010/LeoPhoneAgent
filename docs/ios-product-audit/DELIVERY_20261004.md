# iOS 1.51.0 (138) — three-round audit evidence

Baseline: `61ccd292`. Scope: iPhone/iPad product, iPhone-side Watch configuration and Watch regression checks. Android, Harmony and Mac binaries were not changed.

## Scope of every round

Each round checked all 17 modules: Home, models, catalogs/groups, providers, chat, sessions, content preview/share, attachments, Treasury, files/terminal, voice, remote devices/SSH, sync, skills/MCP/environment variables, automation, settings/privacy and Watch.

Each considered navigation and convenience, input/selection/persistence, empty/loading/error/cancel states, keyboard and accessibility text, phone/tablet layout, continuous actions and privacy. Evidence is not interchangeable: source review, isolated production-component tests and installed-App checks are reported separately.

- **Round 1:** 55 baseline screenshots across physical iPhone/iPad; complete module source review; fixes to Home/model convenience, draft/model resolution, attachment queues, literal search, imports and failure recovery, Watch/host state and sync category/legacy tasks.
- **Round 2:** complete review of different user paths and failure combinations across the same modules. Reproduced and fixed failed note saves, overlapping exports, stale provider validation, duplicate session initialization, stale preview URLs, false alarm/automation success. Watch model search added from the observed long-list problem.
- **Round 3:** complete cross-feature review of the updated product, including delayed completions, moving/recovering/compacting drafts, headless Watch requests and save boundaries. Fixed manual-credential ownership, full Treasury draft context and note metadata commit reporting. Final visual review also exposed a real Home menu hit problem caused by interactive glass on the whole composer; a one-line change to ordinary glass fixed the manual control and automated journeys.

## Boundaries and retained evidence

Both wired and Wi-Fi XCTest runner attempts failed before test execution with the same driver-channel error. This does not establish a Wi-Fi/VPN cause. DeviceHub plus Apple's native screenshot capture supplied physical-device evidence instead; unnecessary runner retries stopped.

During baseline inspection, a moving model sheet caused one accidental group-to-entry selection. The original group and resolved model were restored visually without sending a message. Recent-choice bookkeeping may have changed; exact internal binding metadata was not read back. The private deviation record is retained.

Native fixtures execute production views and methods with synthetic data and explicit external-service adapters. They do not prove all CloudKit/provider/voice/biometric/SSH/OS-background scenarios. Long-running background work, audio interruptions, weak-network handoffs and every third-party provider remain bounded by the actual device evidence; no claim of an absolutely defect-free product is made.

Private raw screenshots, detailed logs, source manifests, original failed results and the 51-row coverage matrix are kept in the task's `ux-three-round-20261004` artifacts and the host's `UXAuditR1` cache. They may contain personal data and are not published with the repository.
