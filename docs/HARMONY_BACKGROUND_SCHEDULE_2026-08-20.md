# 鸿蒙定时任务后台执行调研（2026-08-20）

对应 `HARMONY_FULL_CHAIN_AUDIT_2026-08-20.md` P2.13。结论先写：
**这一版继续只在前台 30 秒轮询。锁屏、切后台、杀进程都不跑。UI 和 README 已写明。**
后台准时执行目前没有一条不申请额外系统能力、且能过个人 hdc 分发的路。

## 现状

`EntryAbility` 在 `onForeground` 里 `setInterval(30s)`，`onBackground` 立刻清掉。
这是 Harmony NEXT 对普通应用的默认生命周期：进后台后 JS 定时器不可靠，很快被挂起。

## 候选方案

| 方案 | 能力 | 为什么这一版不做 |
|------|------|------------------|
| 提醒代理 Reminder / Calendar | 到点弹系统提醒，点开把 App 拉回前台再跑 | 用户还要点一下；需要日历/提醒权限和系统应用配合，不能静默跑 Agent |
| 长时任务 Background Task / 连续任务 | 导航、播放这类前台服务可续命 | 定时对话不是系统认可的长时场景，乱报会审核/杀进程 |
| 延迟任务 WorkScheduler / Idle | 系统空闲时跑短任务 | 不准时（可能晚几十分钟），且后台网络/模型请求仍会被限 |
| Push 唤起 | 云侧到点推一条，拉活 App | 没配 AGC 时 Push 本身不可用；还要一台永远在线的调度机 |
| 当身体由 Mac/iPhone 到点发指令 | 调度放在已开机的中继侧 | 这是现成替代：鸿蒙当身体，定时放在桌面端 |

## 产品边界（已落地）

- `SchedulePage` 写明「目前仅 App 在前台时执行」。
- 失败结果落会话和定时页，避免用户以为「设了就一定跑过」。
- 需要准点无人值守时：把任务放在 Mac / iPhone，指挥这台鸿蒙当身体。

## 以后若要做

最小可用是「到点系统提醒 → 用户点开 → 立刻跑并写入会话」，不要假装后台 Agent 一直活着。
