# iOS 与 Mac 界面、动效和交互审计

基线为 `094d4f8c`。Mac 以下截图来自本次执行中最新源码的真实 React 组件；认证与 API 使用合成空数据，所有写接口拒绝执行，没有连接私人会话、运行模型或调用系统动作。截图包含浏览器外壳及浏览器扩展浮标，它们不属于产品，不能作为产品缺陷。没有用历史截图或本机旧版 1.74.2 替代 1.84.0。

iOS 已做源码动线与动效检查，但本次完整模拟器 App 在设备版 iSH 静态库链接阶段失败；真机 CoreDevice 连接重置。iOS 的视觉、手势、VoiceOver、帧率和硬件结论仍待真机验证。Mac 的浏览器组件审计也不能代替最终签名 Electron App、系统权限或真实后端测试。

## 1. 新任务首页：入口存在，主区仍偏重解释

健康度：**可操作，信息层级需改善**。新任务输入框可写，项目选择按钮可点击；这与历史“新任务是假按钮”的问题不同。空态主区的大标题、说明和三段规则远离顶部任务输入，视觉焦点落在解释文字上。Agent、目标、权限、推理档的小胶囊需要用户先理解多个概念。

下一版：输入区与“当前项目/此 Mac”形成同一操作组，主页保留一句说明和两三个具体示例；默认参数收在可展开详情，项目可延后选择但草稿不能丢。保持已有“新任务→一次提交”逻辑，补提交中的去重和失败恢复，不再重做一套入口。实际字号/对比度与最小窗口需在最终 App 测量，本截图不提供 WCAG 合规结论。

## 2. 项目抽屉：键盘焦点穿透已复现

健康度：**存在已复现的交互缺陷**。点击“选择任务项目”打开抽屉后，焦点仍留在抽屉后方的触发器；按一次 Tab，焦点转到背景“任务目标：本机或远程 Mac”。遮罩与 `aria-modal` 没有形成真实模态焦点范围。Esc 可以关闭抽屉，但关闭后的焦点也没有回到原项目触发器。

源码对应 `ProjectDrawer.tsx:27–60`。下一版复用统一 Dialog 原语，补初始焦点、背景 inert、焦点循环与恢复；不要只补 `aria-modal` 属性。验收包括 Shift-Tab、Esc、嵌套选择器和读屏。证据：[本次 AX 记录](./evidence/mac-drawer-focus.txt)。

![项目抽屉与背景遮罩](./evidence/02-mac-project-drawer-fixture.png)

## 3. 设置 → 外观：分组清楚，但设置内容归属混杂

健康度：**基础布局清楚，分类需要调整**。设置弹窗已有侧栏、搜索、组标题，不能描述为没有设计系统。进入“外观”后第一屏却先展示默认 Agent、默认模型、默认权限模式，真正的密度/减少动态效果/主题排在后面。参数归属与导航名称不符，找外观的人先看到执行策略，找权限的人也不容易预期它在外观页。

下一版将执行默认值归入“Agent → 新任务默认值”；外观保留主题、字号、信息密度、动效、语言。两端保持术语一致，桌面仍使用适合宽屏的侧栏，不强迫照搬手机折叠列表。完整设置首次进入出现的模拟后端错误不计作产品故障。

## 4. 全局查找“藏宝阁”：只匹配 Storage 设置

健康度：**可发现性与本地化缺陷已复现**。打开 ⌘K，输入“藏宝阁”，当前无项目空态只出现“设置：Storage”，没有打开收藏工作区的明确动作。这不是“藏宝阁服务不存在”，而是全局入口没有把已有工作区暴露出来。

源码 `CommandPalette.tsx:373–380` 使用原始 `label`，没有使用设置页自身的 `labelKey`；`settings/constants/constants.ts:71` 的 Storage 关键词包含“藏宝阁”。下一版明确登记“打开藏宝阁 / 搜索收藏 / 快速收集”，显示中文语义，并复用现有工作区，支持无项目使用。不能为了修入口再造第二个收藏库。

## 5. 藏宝阁组件：已有工作区基础，技术配置抢占主位

健康度：**组件基本交互通过，完整导航及后端未在此验证**。这一张是直接挂载原始 `CollectionsMirror` 的隔离组件页，外层为审计容器，不是声称从正式首页完成了整条导航。原组件具备收集框、六个视图、合集、搜索和空态；点击“处理中”后按 Right，选中项与焦点正确移到“失败”，应保留这项无障碍实现。

“手机同步范围 / 元数据 / 正文按需”的技术选项位于内容之上；新增用户首先需要的是“保存什么、在哪里找到、能否离线读”。下一版将同步详情收进“离线可用”菜单，以状态时间戳和明确设备来源保持透明。收集区折为简洁快速输入，粘贴/拖入时展开；正文阅读与高亮成为主区。空态根据收件箱/处理中/失败分别解释，而不是统一“当前视图还没有内容”。

源码额外确认：本地请求固定 `limit:200`，合集清单和选中合集过滤都发生在这批结果内；API没有分页 cursor。超过200条的旧收藏/合集无法可靠从“全部”继续浏览。应先在数据库内完成筛选和排序，再按 cursor 分页，并独立查询合集 facets；不能靠全量拉取修这个问题。来源 `CollectionsMirror.tsx:129,210–238`、`treasury.routes.ts:205–210`。

## iOS 源码动线：保留已经完成的改进

`ContentView.swift:267–270` 已默认折叠昨天/本周/本月/更早；`3100–3114` 的首页输入已走 `sendPrompt`，不是只填入聊天框。六个入口已是网格并有原生按压反馈；设置已是四组、搜索、分组色带与缩进；藏宝阁已有真实宽度驱动的 iPad 分栏、正文、高亮、处理状态。上述都列入回归保护，不重新计作新功能。

本轮新增的设计差额是：①首页六项主要仍是任务入口，未覆盖手电筒等设备动作；②设置“外观”关键词已有“手电筒”，真实能力却不存在；③能力目录缺动作级条件和最近结果；④`LeoMotionEffects.swift` 的运行中循环需补离屏、场景、热状态及运行时 Reduce Motion 切换验证；⑤`CollectionsView.swift:231` 对整个 items 变动附动画，需测高频同步/阅读进度更新是否触发不必要列表过渡。后两项是性能待测风险，不是已经测得掉帧。

## 下一版动效合同

以下是产品设计目标，不是 Apple 强制时长，也不是本次实测值。

| 场景 | 动效与触发 | 中断与降级 |
|---|---|---|
| 高频按钮 | 80–120ms 即时按压，缩放约0.97–0.99；释放用现有 spring | 取消按压恢复，键盘同样有反馈；不使用示例0.88的夸张缩放 |
| 任务进入运行 | 状态标签与任务行连续变化，约180–240ms | 仅接受真实 run 状态；不能定时器伪造成功 |
| 审批出现 | 小幅淡入，内容/目标/后果先清楚；一次触觉提示 | 不循环闪烁；取消/他端已处理即时反馈 |
| 完成与产物 | 新产物原位出现，一次短提示与可打开预览 | 历史回放不重播庆祝；失败仍保留部分产物并标状态 |
| 设置折叠 | 高度变化与箭头同步，约220–280ms | 不固定100px max-height；中途反向可接续，焦点不被裁掉 |
| 藏宝阁收集 | 输入变保存收据，再进入准确处理状态 | 保存成功与OCR/转写完成分开；不等增强才确认收下 |
| 语音 | 真实音频电平驱动轻量波形，录音/识别/整理明确分段 | 来电、耳机拔出、权限拒绝时停止；Reduce Motion静态状态 |
| 长流式列表 | 保留滚动锚点、稳定key，批量合并刷新 | 用户上滚不拉回；历史不逐条入场；离屏停止装饰 |

Leotexiao参考选择：026 Squish Button、006 Accordion Spring、057 Status Pill、016 Copy Button、064 Step Progress。只借触发和反馈思想，不复制演示里的固定高度、假计时完成、无取消的指针事件代码。iOS继续使用 `LeoMotion/LeoHaptics`，Mac继续用现有 CSS tokens 和 React；基础交互无需新增 GSAP/Lottie/Rive。
