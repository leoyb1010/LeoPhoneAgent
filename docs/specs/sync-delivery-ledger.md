# Revision-safe durable destination delivery

`SyncDeliveryLedger` uses the existing ChatStore SQLite connection. The legacy dirty table remains the source of pending local mutations; AFTER INSERT/UPDATE triggers atomically increment a persistent per-object revision head and replace one delivery ticket for every configured durable destination. Heads survive queue cleanup and explicit cancellation, so revisions cannot reset when the same object is recreated. `changeId` is generated once per revision and shared by all destination tickets.

Existing pending V2 dirty records seed iCloud exactly once. Reopening a database or reconfiguring an existing destination cannot recreate an already acknowledged ticket. Adding a new destination seeds current dirty records; it does not falsely acknowledge historical data. The caller must explicitly stage a full existing-data snapshot for a newly enabled replica. Disabling a known destination pauses sends but preserves its tickets and captures subsequent edits; pending disabled destinations keep the legacy dirty row but do not keep the scheduler running.

ACK is conditional on destination + object + revision + changeId. A stale or duplicate ACK cannot clear a later edit or another destination. The compatibility dirty row is deleted only when all destination tickets for the current revision are gone. Direct deletion from the dirty table means explicit cancellation, which cancels its tickets; it must never be used for a V2 successful send. Permanent failures and unavailable builders/files remain durable blocked tickets, exposed through `syncDeliveryFailures()`. Manual retry or a new local revision clears the block.

PortableRecord payloads are frozen once per revision. All destinations and retries read identical JSON. Local assets are copied off the main actor to private outbox snapshot files, checked for byte count and synchronized before the payload pointer is stored in SQLite. Network transports replace those local paths with their own hash references. Stale hydration cannot freeze a ticket after a newer dirty revision. Snapshot directories are reclaimed after sends only when no destination has a live ticket for the change ID; disabled/blocked destinations retain their assets. Copying does not materialize whole attachments in RAM.

The existing appendMessages transaction already encloses message/session mutation and dirty capture. Session title/pin/delete and local message/compact-marker update paths now use nested savepoints around business mutation and dirty capture, with dirty persistence errors triggering rollback. File-system operations and separate ArtifactRepository/config stores are not magically part of SQLite's transaction; their existing change trackers/reconciliation remain required.

Inbound processing is now awaitable. Observe and fetch callers wait for per-type merge/deletion callbacks before calling the transport's `acknowledgeInbound(batch)`. Unsupported schema, a missing merger/deletion callback or cancelled processing withholds that checkpoint. Receive handlers no longer use UploadPolicy; disabling uploads cannot drop peer records or tombstones. Record-ID-only echo suppression was removed because a peer can legitimately edit the same ID during the send window. The legacy mergers currently return Void; a completed callback alone does not prove every domain persisted data successfully. A durable receive inbox or throwing domain-merge contract is still required to cover silent merger failures, and the parent integration owns that follow-up.
