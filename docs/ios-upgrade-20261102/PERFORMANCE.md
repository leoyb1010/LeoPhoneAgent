# 性能修复范围与验收

用户要求先修性能，再对 Pro Max、新 Duo、iPad 覆盖安装。不卸载、不清空数据；不以历史预算例外代替修复，不改变预算阈值，不删除历史记录。

证据：三台仍为 1.87.1。Duo/Pro Max 的 perf.jsonl 存在 3438 条完全相同的迁移历史。Pro Max 的 2729.9ms 回前台记录中 first=103.5、active=2691.6、stall=116.7，fg.steps 合计约1.4ms，不能称为2.7秒主线程阻塞。Duo单次268.9ms流式停顿来自历史时间戳；当前短滚动高hitch仍须实测，不因历史迁移而忽略。

修复：
1. 前台恢复不在一次主线程回调中刷新全部暂停会话；最近活跃会话优先，每帧恢复一个，失活立即废弃队列；保留最终文字、工具状态及列表通知。
2. 完成文字块的 Markdown/富文本缓存绑定原文，内容未变则复用，内容变更和主题清理仍失效；避免完成与恢复重复全量解析/渲染。
3. 滚动计时在失活/后台收尾，不把后台间隔计入滚动；性能记录附 build、当前进程run和本机不迁移标识，历史数据不改。中断样本显式标注，不静默删除。

验收：真实控制流回归、缓存失效/复用回归、正常卡顿仍计入与后台分段回归、完整构建与原生重负载测试；新Duo当前基线及修复后运行样本独立保存。未得到足够新样本的预算标记未验证，不写成PASS。
