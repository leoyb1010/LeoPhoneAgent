## 安装事务

```text
冻结源码 → 构建 → 同团队签名校验 → Apple Accepted → 钉章与隔离属性验收
  → 每台空闲检查 → 本机暂存与校验 → 旧App保留回滚 → 覆盖 /Applications/LeoBot.app
  → GUI会话启动 → 原数据根保留 + 版本 + 本机健康接口 + 中继在线 + 渲染验证
  → 该台通过后移除其旧App副本 → 下一台
```

只替换 App bundle。配置、会话、配对和资料保留原路径；数据留在设备本机。回滚快照放在该机受限目录，不带到其他机器，不打印密钥。旧 App 与旧安装包仅在新版本正常后清理；不将配置、数据库、资料当作旧副本删除。无权限目录的核查范围如实记录。

公证使用既有钥匙串 profile；不中途因等待重投。部署复用已有机群入口和它的签名/回滚/中继检查，不把编译或版本回读替代实际启动。记录四台版本、签名、产物摘要、启动/健康、中继、原数据目录和旧副本清理结果。

## 本地公证票据的安装边界

本轮实际 Studio 验证发现：同一签名已获 Gatekeeper 接受，但 SSH 在已安装 App 内补写票据会被系统 App Management 拒绝。发行公证脚本产出的 ZIP 包含已钉章 App，DMG 内 App 未重新写入票据。部署入口先验证 DMG 内 App 的本地票据；缺失时只接受配套 ZIP 中通过深度签名和本地票据验证、且主 CDHash 与 DMG 一致的 App，之后再进入原暂存/覆盖/健康流程。不得以修改 TCC、关闭 Gatekeeper、放宽权限或忽略票据错误处理。
