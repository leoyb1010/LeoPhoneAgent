# 首页任务结果与密钥控件可访问性

## 所有者与范围

任务元数据和 sessions-index activity 已有唯一所有者；首页只做派生展示，不新增持久状态或改变任务执行。
从当前任务 → getTaskListRowActivity/deriveTaskLeadingIndicator → 首页分组 → 选择既有任务。

## 状态规则

- 等待用户回复/确认先显示
- 实时 error 且有未读结果显示「出错待看」，不能写「做完待看」
- 无实时 activity 时可使用持久化 status=error；实时 running/success 覆盖旧的持久化 error
- 运行及后台工作保留原判定；其余未读终态沿用「做完待看」（中断终态的细化提示仍需单独回归，不据此宣称所有终态已优化）
- 已读静止任务仍不挤占首页；同组顺序保持输入顺序
- 失败状态同时使用文字和 destructive 色，不能只靠颜色

## 验收

纯函数测试覆盖实时失败/持久失败/已读/恢复运行/后来成功/待审批优先级。
真实 renderer 合成工作区验证红色失败标签、点击打开任务、重复打开及窄窗布局；不得用测试卡片代替完整原生桌面集成。

## 密钥输入

显示/隐藏密钥按钮必须有随状态改变的双语可访问名称和 aria-pressed；输入有独立名称。
不改存储、登录或readOnly授权语义，不使用真实密钥。

## 首次没有模型时的恢复入口

实际1024px桌面首用图中，模型缺失说明被单行省略号裁切，动作只写Set/配置。该状态必须完整展示如何接入模型，并把现有动作明确命名为Model settings/模型设置。仅模型未配置提示允许换行；其它有详情弹窗的错误保持原摘要/详情层次。不改变路由、provider写入或模型执行。

验收保留实际Welcome→空provider→设置返回→Home入口。读取model settings标签/空态的computed色值、字号及背景链；用合成无效域名作为Base URL编辑离开/重进并确认保留，取消新增模型不能留下空模型。不得使用真实API密钥或发送模型请求。

## 列表加载失败不是空列表

Controller仍为任务列表的唯一权威；hook只拥有请求生命周期和最后一次成功的显示结果。

请求/手动重试 → hook请求代次 → 既有registry/controller → 当前代次才可提交结果或失败 → 首页状态与旧列表

- 首次加载显示加载状态；没有workspace才直接回到真正空态
- Controller缺失/请求失败显示可理解的错误和具名重试按钮，不伪装为没有任务
- 失败保留最后成功的列表，明确它尚未刷新；重试加载时保留旧列表，成功才替换
- 新请求使旧成功/旧失败失效；effect清理/卸载使在途回执失效，不以Task/Promise实际取消作为保证
- 重试使用既有manualRefreshSerial使缓存失效，不建立新的服务或数据cache
- 普通Web缺失controller仍是正式产品集成缺口；错误可理解只是恢复反馈，不代表Home/history功能修复完成

验收：故障→保旧→重试恢复、旧成功/旧失败晚到、卸载、无scope取消。真实Web采集可见错误和重试，原Home任务集成断言仍保留；真实Electron恢复与历史/未读持久读回保持原门。

## 模型设置导航标题可读性

实际renderer的Custom providers 12px标题computed对比度2.4047:1；局部标题使用既有text-foreground-subtle，不改全局主题。真实同环境采样必须确认所有祖先opacity=1且标题文本solid-background对比度≥4.5；保留原图和计算前提，不推广为整个界面无障碍认证。
