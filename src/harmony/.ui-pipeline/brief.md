# LeoBot 鸿蒙界面交付标准

用户要求 UI、UX、布局、设计、按钮和动效全部精致高级。沿用 LeoBot 当前 iOS 机器人标识与青绿强调色，在原生 ArkUI 中完成。

## 真实旅程

首次连接模型并发送消息。日常聊天保留实际模型、草稿、附件与阅读位置。第二大脑能看见来源和访问状态，上传、审批和分享有真实回执。失败时可恢复，用户输入保持可用。

## 已选方向

暖白和石墨色形成安静的阅读背景，青绿只承担主要操作与选中状态。标题、正文、来源、状态分开层级。三折叠展开后列表收窄，正文保持720vp可读宽度。表单限宽520至560vp。窄屏优先保留输入和当前任务。

所有交互保持原生控件、44vp触点、键盘焦点、读屏标签、浅深色与系统字号。加载使用真实请求状态，不按计时器伪造成功。弹窗说明实际对象、参数与结果不确定性。

## 动效

参考 leotexiao 的 Squish Button 与 Submit States 节奏，只采用交互反馈和真实状态切换。按下80ms，释放220ms短回弹，图标120ms。常用控件幅度0.98，图标0.93；导航最多轻微位移与透明度变化。流式文字、滚动列表与大媒体不逐帧追加装饰动画。减少动态效果跟随系统，状态信息与操作保持完整。

## 实测问题与证据

6.1.1真实模拟器已跑通正常UI配置与SSE消息。默认OFFSET避让会把对话历史移出屏幕，输入操作行被键盘裁切，保留了composer-keyboard-before.jpeg。当前已改UIContext RESIZE、内容自测量与紧凑模式，需新候选安装后重测。

最终检查包括单/双/三屏、Pura X Max内外屏与横竖屏、键盘出现/隐藏、长文本、加载/空/错误/权限撤回、重复点击、按压中断和减少动态效果。源码或构建通过不能替代渲染与交互证据。
